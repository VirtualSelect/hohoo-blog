# 文章阅读工具：复制受限时的完整代码回退

状态：`codex/content-search-20261111` 本地未提交；没有合并、推送或部署。本记录只描述本轮增量，不覆盖同分支上已保留的检索、系列导读等改动。

## 问题与处理

读者点击正文代码的“复制”，在浏览器无法写入剪贴板时，旧实现仅短暂显示“复制失败”，没有可操作的下一步。本轮保留正常复制行为，失败后打开原生对话框，提供自动全选的只读完整代码。关闭或按 Escape 后，焦点回到触发按钮，读者无需重新寻找阅读位置。

代码来自当前渲染的代码块，不复制截断预览，不请求额外接口。英文、简体、繁体复用既有语言系统，样式复用图片查看器的对话框和主题变量。没有新依赖、付费请求或浏览器权限更改。

变更文件：

- `apps/web/components/CodeCopyDialog.tsx`：仅在失败时呈现的手动复制对话框。
- `apps/web/components/Document.tsx`：完整代码回退、文章身份检查、焦点恢复、文章/语言变化时清空状态。
- `apps/web/app/editorial.css`：对话框宽度和可滚动只读代码区。
- `docs/CONTENT-MODEL.md`、`docs/ROADMAP.md`：同步行为与下一步。

## 实际浏览器验证

验证路径：文章代码按钮 → Clipboard 写入 → 成功反馈，或失败 → 完整只读文本 → 系统复制 → 关闭恢复焦点。该流程不依赖服务端 API、数据库、环境密钥或第三方模型。

1. 正常 `http://localhost:4216/docs/ai-apps/java-first-llm` 点击复制显示“已复制”，没有打开手动窗口。
2. 本机非回环 HTTP 地址上出现真实的自动复制失败，窗口中的118字符与触发代码完全相同、全部选中；Escape 关闭后焦点返回 `copy-code`。该临时标签页已关闭。
3. 长代码仍处于视觉折叠时，回退字段包含全部296字符，而不是可见部分。系统 Ctrl+C 后读取本次测试文本，与原代码相同；关闭恢复原按钮。没有读取其他剪贴板内容。
4. 另外使用仓库忽略目录中的本地代理，显式模拟 Clipboard 拒绝，窗口标注“本地验证 · 复制失败模拟”。1440、1280、1024、768、430、375宽度均测得窗口位于视口内，字段全文一致且全部选中；375×667的关闭按钮可见。三语言文案、夜间和护眼模式已检查。
5. 代理仅服务本机已有预览，测试脚本不进入产品代码或构建输出；验证完成后已停止。不能将模拟失败当作所有浏览器都会拒绝复制的证据。
6. 手机目录使用 Enter 展开、Enter 激活标题，标题落在视口上方约100px处；桌面目录点击和 Enter 跳转、当前位置高亮均正常。锚点滚动有过渡，落点在滚动结束后检查。
7. MuJoCo 首篇图片通过“放大图片”按钮的 Enter 打开，375×667内完整加载；关闭按钮和 Escape 关闭均恢复 `image-zoom` 焦点，夜间也正常。目录与图片查看器未发现需修复的问题，因此没有修改其实现。
8. 正常本地预览所检查页面未捕获控制台 error。最后恢复默认视口和护眼模式，保留正常4216预览。

截图及弹窗边界记录保存在工作区制品目录：`manual-code-copy-20261112.png`、`manual-code-copy-mobile-20261112.png`、`manual-code-copy-light-20261112.png`、`reading-tools-widths-20261112.json`。前两张记录实际/策略受限时的窗口，护眼截图和宽度记录明确使用本地失败模拟。
