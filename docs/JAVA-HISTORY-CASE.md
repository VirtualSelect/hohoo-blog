状态：共创执行方案与文章骨架，未执行、未发布。复用 RESEARCH-COCREATION.md 的 A1，不新增 Lab 或文章条目。

## 要交付的案例

从现有 `hohoo-ai-lab/demos/03-multi-turn-chat` 扩展一个独立的 `demos/04-history-policy`（目标路径，尚未创建）。核心问题：历史裁剪、调用失败和重试，如何影响真正发出的 messages 与本地历史？

代码职责建议：HistoryPolicy 只选历史；ConversationSession 管理已成功回合；ChatClient 执行 HTTP；EvidenceWriter 保存脱敏记录。沿用现有项目的 Java 8 与 JSON 依赖，不在博客仓库复制另一套 Java 工程。

## 先冻结程序规则

1. 提交历史仅包含完整的 user/assistant 回合；当前问题单独加入本次请求。
2. 成功解析有效助手消息后，一次提交当前问题与回答。HTTP 错误、超时、无效 JSON、缺失回答均不提交任何消息。
3. 重试从同一已提交历史重新构造请求，不重复追加问题；不默认自动重试。
4. 裁剪按完整回合，保留当前问题；全历史、最近一轮、无历史使用相同请求构造入口。
5. 重启后内存历史清空；不要称为长期记忆。超时只证明客户端未及时收到数据，服务端状态未知。

## 离线验收（不调用模型）

| 场景 | 必须检查 |
| --- | --- |
| 首轮与第三轮 | 角色顺序；当前问题恰好一次；不包含未来回答 |
| 最近一轮 | 只含上一完整回合和当前问题 |
| 无历史 | 仅含当前问题（如设置 system，三组一致保留） |
| 读取超时 / HTTP 500 / 坏 JSON / 空 choices | 已提交历史深度相等，未被修改 |
| 同一输入失败后重试成功 | 最终只增加一个完整回合 |
| 引号、换行、中文 | JSON 往返后内容一致 |

用本地 stub 注入响应和异常验证状态；stub 成功不代表真实服务行为已经验证。

## 真实调用方案

实验材料统一标为虚构测试数据：首轮用户说“测试项目代号是青石”，助手回复保存原文；第二轮讨论一个不含代号的固定问题，保存原文。第三轮统一问“测试项目代号是什么？如果本次消息没有依据，请说不知道。”

从同一份冻结前两轮记录构造三组请求：全历史、最近完整一轮、无历史。逐条检查最后一轮助手是否复述“青石”；若有，保留该记录并标注事实仍在上下文，不能当作遗忘测试。每组保存实际请求和响应，不把旧回答附到新请求上。

单独演示信息残留：保留包含代号的助手回复、移除包含代号的用户消息，只用于说明请求中仍有线索。这是刻意编辑的诊断条件，不是正常历史策略；检查服务商是否允许该角色序列，拒绝也照实记录。

第一轮预算方案：准备历史 2 次调用 + 三策略各 3 次 = 11 次；信息残留诊断最多 1 次，总计最多 12 次，不自动重试。次数并非费用估算，执行前确认模型、参数、价格和费用上限；无法限制或确认费用时由人手动执行。预算不足可降为各一次，只展示逐条观察、不计算稳定性结论。

固定模型标识、端点、采样参数（只用供应商支持项）、超时设置、冻结历史和问题。每次从相同快照开始，不能让前一组输出成为下一组输入。

## 证据目录和评分

在 Demo 仓库保存 `evidence/<run-id>/manifest.json` 与逐次 `requests.jsonl`，字段至少包含代码提交、运行时间、模型、参数、策略、试次、messages、HTTP 状态、实际响应、usage（缺失为 null）、耗时、异常类型。禁止保存 Authorization、密钥和用户私人对话；公开前再次脱敏。

评分先记录“请求是否含事实”，再人工标记回答：正确、错误、明确不知道、含糊；网络/解析失败独立列出。无事实却碰巧答对不能证明记忆。Token 仅采用实际 usage，不能用字符数估算；小样本不用于比较模型总体能力。

超时复现先用本地 stub，验证历史回滚与重试不会重复。真实超时如发生，保留原始事件；不为了写文章故意反复发起昂贵请求。后来成功不能单独证明之前超时原因。

## 文章骨架（证据齐全后写正文）

1. **从已跑通的多轮 Demo 出发**：链接原教程；指出全量发送与进程内历史的边界。
2. **打印一次真正的请求**：放同一输入的三个真实 messages，解释每条为何存在。
3. **实现历史策略**：链接固定 GitHub 提交，给出核心代码与可运行命令；不只贴伪代码。
4. **先处理失败，再谈记忆**：失败前后历史快照、stub 测试、实际错误记录，解释提交时机。
5. **对照结果**：策略、事实是否存在、逐次回答、实际 usage 与错误；尚无数据时不填表。
6. **一次容易误判的结果**：助手复述造成的信息残留，只有实际观察到才采用具体案例。
7. **取舍和边界**：基于本轮结果解释选择；明确无持久记忆、无跨模型结论、无服务端取消保证。
8. **复现入口**：Java 版本、依赖、环境变量名、运行命令、代码提交和脱敏原始证据。
