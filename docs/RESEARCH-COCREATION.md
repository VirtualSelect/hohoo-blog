## A1 · 有边界的 Java 对话助手（AI 应用开发）

目标：把已有 `hohoo-ai-lab/demos/03-multi-turn-chat` 扩展为行为可验证的对话程序。新代码属于该项目，不另造一个“已上线产品”。

- [ ] 人：复现既有 Demo，确认 Java 环境、当前可用模型与调用预算；提供脱敏日志。
- [ ] AI：在独立 Demo 中实现全历史、最近完整一轮、无历史三种策略，明确保留当前问题。
- [ ] 人 + AI：先写断言：消息顺序正确、输出成功后才追加助手、失败不残留未完成回合、重启不保留内存历史。
- [ ] AI：用离线 fixture 测试协议/状态行为；明确它不能证明真实模型效果。
- [ ] 人：批准后执行真实对话，包括普通输入、包含引号、已知事实追问与读取失败。
- [ ] 人 + AI：逐条核验输出，保留请求/响应、模型标识、参数、时间、代码提交与错误，不保留密钥。
- [ ] 共创交付：可运行 Demo + 一篇失败处理复盘 + 项目限制说明。先审阅再发布。

验收：程序状态断言通过；真实运行可追溯；超时不得表述为“服务器没有执行”，重试成功不得单独证明故障原因。

## L1 · 同一事实换个位置，模型还能找到吗？（LLM）

研究问题：固定任务与模型，在上下文开头/中间/结尾放置一个明确事实，加入固定干扰文字后，回答是否引用正确？这与 A1 的程序实现不同，关注模型行为。

- [ ] 人 + AI：共同写 6 个小型虚构事实题，每题答案明确；材料标记为人工实验数据，不能当作用户真实信息。
- [ ] AI：构造固定材料的三种位置版本，以及删除事实的无证据对照；保持问题、模型、采样和输出格式一致。
- [ ] 人：审定评分规则（正确 / 错误 / 明确不知道）、每种条件的重复次数与预算，执行前冻结版本。
- [ ] AI：提供可运行脚本、逐题 JSONL 记录模板与配对结果表；先 dry-run 展示预计请求数，未经批准不调用 API。
- [ ] 人 + AI：检查事实是否被助手回答或题目泄漏，避免“删除了用户消息但助手仍重复答案”的混杂因素。
- [ ] 人：执行真实调用并人工复核；失败/超时单列，不混入语义正确率。
- [ ] 共创交付：一篇真实 Lab、一份可复现数据与“上下文并非长期记忆”的短 Note 草稿。

验收：保留所有条件与失败记录；报告各条件样本量与不确定性。不以这个小实验宣称模型总体优劣，不把字符串长度当作 Token 数。

## E1 · 固定目标的抓取偏差对照（具身智能，复用 VL01）

这是现有 VL01 的首个可验证小案例，不新增第五个仿真实验计划。

- [ ] 人：提供系统、硬件与可用运行环境；共同确认 MuJoCo 示例场景与模型许可。
- [ ] AI：将依赖版本、场景文件、启动方式和坐标系写入 `hohoo-embodied-agent` 的复现说明。
- [ ] 人 + AI：固定机械臂、物体、控制器与终止条件，只改变目标位置偏移量；先约定偏移组、重复次数、种子和成功定义。
- [ ] 人：实际运行基线和偏移组，保留原始轨迹、接触/终止日志及视频。
- [ ] AI：基于日志计算到达误差、失败类型；图表只能从保存的原始数据生成。
- [ ] 人 + AI：区分控制误差、碰撞、坐标错误与抓取失败，不能将“到达目标点”直接当成“抓取成功”。
- [ ] 共创交付：VL01 关联的真实 Lab + 复现脚本 + 一段场景演示。结果核验后才更改既有状态。

验收：其他人可按环境说明重放；浏览器网格示意不算 MuJoCo 运行证据，不从仿真结论推断真实机器人效果。
